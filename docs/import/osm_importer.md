# OpenStreetMap importer preparation

Document state: 2026-10-04

## Current capability

Source acquisition, tag mapping, source geometry and local walking-file preparation are implemented. The full administrative import is unfinished: database publication, fact reconciliation, exclusion, uncertain-commit recovery and pointer activation remain pending. No current operation reports an updated database copy.

A running HTTP backend is not needed. The future complete import reuses the documented shared engine, clock, logger, exclusion and vote evaluator without starting the API process. This implementation adds no backend_skeleton work.

## Source and temporary storage

The source is the dated Małopolska extract selected by Geofabrik's latest redirect, over HTTPS. The URL, MD5 and source header must validate. Source freshness is the header instant shown in Europe/Warsaw, independently of download time. Source edit dates belong to their original elements. Missing or contradictory accessibility information never confirms accessibility; contradictory explicit tags produce unknown and no fact.

`fetch_osm_extract` is an asynchronous context manager. Call it with the HTTPX client returned by `build_osm_http_client` and an absolute monotonic deadline from the running event loop. Its returned path is usable only while the context is open; all downloaded bytes are removed on exit. Transport requests have no automatic retry or fallback source.

## Local preparation API

`prepare_osm_network_data(source_path, network_path)` reads a local source and writes a new network PBF. `prepare_osm_routing_data(source_path, directory, template, tool_directory, deadline)` additionally builds walking tiles and a manifest. Supply a complete Valhalla configuration generated by the delivered 3.9.0 tools and the directory containing valhalla_build_tiles and valhalla_build_extract. The project's image definition is valhalla/Dockerfile; this operation does not build or start that image.

The output directory must not exist. Preparation stores network.osm.pbf, build.json, valhalla_tiles.tar and manifest.json. The configured platform and node-identity options are forced to true; transit inputs are removed. Source nodes and ordered references survive selection; crossing ways are retained whole. Existing data is never overwritten. Failed unpublished output requires the final orchestrator's guarded cleanup; do not activate it or remove any committed copy.

The manifest checks source state, sizes and SHA-256 hashes. It proves file completeness against its recorded contents, not database commit or the copy loaded by a running router. No current pointer is written by preparation.

## Verification and limits

Run `python -m pytest tests/service tests/data tests/architecture/test_osm_import_boundaries.py` with the pinned project dependencies. Tests use invented files, HTTPX mock transport, controlled tile tools and local synthetic processes; no production database is read or written. They cover source rejection, cleanup, incomplete boundaries, holes, normalization, integrity verification and child-process cancellation.

Real tile construction and a full Geofabrik run remain unverified. Synchronous source parsing still needs the final wrapper's process-level timeout enforcement. There is no production launch command until the full worker operation and shared infrastructure are connected; python -m worker.osm_import remains its planned entry point.

## Provenance and use

OpenStreetMap contributors provide the underlying data. The app retains the visible OpenStreetMap attribution required by the specification. Source terms and attribution: [OpenStreetMap copyright and ODbL](https://www.openstreetmap.org/copyright). Accessibility tags can be incomplete, inconsistent or outdated; an unavailable or invalid source fails the refresh and must preserve the last committed copy once publication is implemented.

## Database adapter setup

Install the local database package before root dependencies: `python -m pip install ./db`, then `python -m pip install .`. The adapter requires accessibility-db 0.1.0 and SQLAlchemy 2.1.3; it imports the shared models rather than maintaining another schema. `build_osm_database_network` prepares network rows, and `apply_osm_network`, `apply_osm_present_facts` and metadata operations accept an already guarded publication connection. They never commit.

This adapter does not provide the administrative command, shared engine, exclusion, vote evaluator or publication recovery. No live connection is configured in this checkout. PostgreSQL execution and production schema compatibility remain unverified; compiling queries and passing local tests do not prove a completed import.
