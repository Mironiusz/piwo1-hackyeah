# deploy - shared decisions

## 2026-10-04 - The Compose project of the hosted demo (plans/deployment_config)

- What changed: `deploy/compose.yaml` is the project `enableme` of the hosted demo: `proxy` (nginx with the frontend build), `backend` (`python -m api`), `routing` (built from `valhalla/`), `database` and `migrate` taken from `db/compose.deploy.yaml` with `extends`, and the one-off `loader` under the profile `load` for the import, the public transport import and the tile step. `database` and `routing` sit only on the network `internal`, which has no way out; `proxy`, `backend` and `loader` also sit on `edge`. The environment file is `.env.demo` in the repository root, and twelve container paths and addresses are set by the Compose file itself (`plans/deployment_config/DEPLOYMENT_CONFIG_PLAN.md` D-4 - D-12).
- Why: one start command and one environment file for the whole demo, with the database defined once in `db/`, no outgoing access for the routing service and the database (M2), and no address of a person in the log of the proxy (`plans/deployment_config/DEPLOYMENT_CONFIG_PRD.md` FR-6, FR-10).
- Reusable pattern: the backend image is built `FROM` the routing image through `additional_contexts` with `docker-image://enableme-routing:local`, because Compose 2.29 does not accept `service:`; so `build routing` runs before any build of the backend. The proxy overwrites X-Forwarded-For with `$remote_addr` instead of appending, because the gateway of the Docker network lies inside the trusted subnet and uvicorn would otherwise take a forged entry; it passes `/api/` through a variable with `resolver 127.0.0.11`, so a recreated backend is found again without restarting the proxy. A check of what the backend sees behind the proxy runs a throwaway container of the backend image with the network alias `backend` and the uvicorn settings of `api/__main__.py`.
- Risk / notes: the published tag `ghcr.io/mironiusz/valhalla-a11y:3.9.0-a11y.1` predates the start script of the routing service and must not be used as the routing image until a newer tag is published (`plans/deployment_config/DEPLOYMENT_CONFIG_REVIEW.md` O-1). Emptying the database removes `enableme_import_workspace` too, because the workspace belongs to one database. The access log of the proxy logs a view path as `/index.html`. A shell command that names `.env.demo` after `--rm` is refused by the dangerous commands hook, so such a command is split. The first local import in `loader` failed on a broken multipolygon of OpenStreetMap that `data/osm_reader.py` treats as a failure of the whole read (`plans/deployment_config/DEPLOYMENT_CONFIG_REVIEW.md` O-8), so the configuration was verified without routing data.
