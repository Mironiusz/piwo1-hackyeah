## 2026-10-04 - The database package, its first revision and its tests (plans/schema_first_revision)

- What changed: `db/` is the package `accessibility-db` (import `accessibility_db`) with the shared model of the seven tables and six closed lists, the chain of revisions in `accessibility_db/migrations/` with `0001_target_schema`, the database image and two Compose files: `db/compose.yaml` for the local database with the profiles `migrate` and `test`, and `db/compose.deploy.yaml` for the hosted demo with a named volume and the profile `migrate`.
- Why: Kuba decided the model and the revisions are a library of their own that does not wait for `backend_skeleton`; the import and the backend install it.
- Reusable pattern: a pair of an instant is one `OffsetInstant` attribute built by `build_instant_pair`; SQLAlchemy 2.1.3 refuses a composite named like its own column and keeps an attribute for every column of a composite, so the columns go under private keys (`key="_cast_at"`), and a nullable pair needs `return_none_on` passed explicitly, because the automatic one does not apply to an explicitly named composite class. A grant to a role whose name is not in the repository is `SELECT set_config('<package>.<name>', :value, true)` followed by `DO $$ BEGIN EXECUTE format('GRANT ... TO %I', current_setting('<package>.<name>')); END $$`, so the name travels only as a parameter. The critical tests run in the container of the profile `test`, after the profile `migrate`, each inside a transaction rolled back after it, and assert a refusal by `psycopg.Error.diag.constraint_name` in lower case. A test that compares the stored objects leaves out what an extension owns (`pg_depend.deptype = 'e'`), `alembic_version` and the not-null constraints PostgreSQL 18 keeps with `contype = 'n'`.
- Risk / notes: the local database lives in `tmpfs`, so it is empty after `down` and a large import fills memory; the database of the hosted demo applies the chain only with `-e DB_REVISION_CONSENT=apply`; the tests open their own engine in `db/tests/conftest.py`, a second place that opens a connection once `data/engine.py` of the backend exists; the root `pyproject.toml` excludes `db` from `deptry`, which `db/pyproject.toml` covers on its own.
