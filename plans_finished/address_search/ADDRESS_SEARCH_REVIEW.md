### Decisions taken while writing code

- Agent decision at C:40, without asking: a result without the key `address` is refused as `invalid_body`, the same as an `address` that is not an object (D-5). With `addressdetails=1` the public instance always sends it, so its absence is a body that is not the expected JSON of `plans_finished/geocoding/GEOCODING_PLAN.md` D-11.
- Agent decision at C:40, without asking: `elapsed_ms` of the error entry of D-10 measures the outgoing call alone, from the end of the wait at the gate to the failure, so a timeout reads about 5000 ms.
- Agent decision at C:40, without asking: the error entry of D-10 is written with `logger.exception` in place of `logger.error(..., exc_info=True)`, because the ruff rule G201 of the `G` set refuses the latter; both write the same ERROR entry with the traceback.
- Agent decision at C:40, without asking: the data layer chains its `NominatimRequestError` to the HTTPX exception with `from error`, as `data/valhalla.py` and `data/osm_source.py` do. The chained exception never reaches a log line, because `DiagnosticFormatter` renders only the frames of the outer traceback, without any message; the log test of S-9 confirms it.

The search needs no database, and this keeps its tests free of one.

Risks:

- R-1. `SearchCache` removes an expired answer only when the same key is looked up again, and otherwise only when 1000 newer answers push it out or the process restarts (D-8). An answer nobody searches for again therefore stays in the memory of the process after its 24 hours, unreachable but present, while `ADDRESS_SEARCH_PRD.md` FR-6 says the memory keeps a text for at most 24 hours. The implementation follows D-8 exactly, so the gap lies between FR-6 and D-8. In this project it has no effect, because the hosted demo and its process are deleted on 2026-10-04 (`CLAUDE.md`, section Target environment), so no process lives 24 hours; a longer-lived service would need the expired entries dropped on every store.
- R-2. `agent_docs/memory/api/_shared.md` asks for `api/API.md` and `api/API_ALGORITHM.md` with the first product operation, while D-13 gives the API layer no document pair, because `api/address_search.py` holds no domain rule, the criterion of `docs/standards/standard_documentation.md`. `plans/route_planning/ROUTE_PLANNING_PLAN.md` S-16 creates the pair; it should name `search_address` when it does.
- R-3. `docs/standards/standard_architecture.md`, section Calls to external systems, sends a blocking call on the request path through a thread pool. The search makes a non-blocking call on the event loop instead (D-1), which meets the purpose of that rule without a thread; the departure is recorded in D-1, in `MVP.md` D-3, in the section Address search of `service/SERVICE.md` and in `agent_docs/memory/_cross_cutting.md`.
- R-4. `build_app` is edited by `accounts`, `route_planning` and this initiative; a merge may conflict there. The repository-wide gates are red on the in-progress files of other sessions, which a Merge Request of the whole tree has to settle first.
