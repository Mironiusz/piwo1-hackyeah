## Decisions

D-1. Retain the source, reader and acquisition contract already chosen in the source initiative. This work does not introduce Overpass or another fallback. Dependency decision adopted from F-4 and F-5, not a new source choice.

D-2. Follow the current specification wherever historical mapping artifacts differ. In particular, an unlisted smoothness value must not become an explicit absence through surface fallback, and an area tagged as an elevator is not automatically a point-elevator fact. Test both divergences. The PRD is reconciled with version 10 (F-3), retaining anonymous vote hashes until demo deletion and detached-account vote history. Agent decision at C:40, without asking: the specification's precedence is explicit, and this does not authorize changing product behavior (F-3, F-14).

D-3. Keep source acquisition and persistence in data, product decisions in service, and the administrative trigger in worker. Reuse the shared connection, configuration, clock, logger and vote-rule interfaces the backend owner supplies. No substitute infrastructure is built to bypass Q-1. Agent decision at C:40, without asking: the layer and shared-helper standards already require this (F-13).

D-4. Use the same source-state comparison for the first import and refresh. A source state equal to the latest osm_copy.state_at yields unchanged; an earlier state fails; a later state can proceed. No publication is attempted for unchanged or skipped runs. Dependency decision adopted from source D-5 and PRD FR-10.

D-5. Complete download, checksum, header validation, boundary assembly, reference checks and derivation before starting the publication transaction. Hold import exclusion from before the download until publication ends. The lock must survive that separation without keeping a write transaction open during network waits; its connection and lifetime depend on Q-1. Agent decision at C:40, without asking: this combines the already agreed exclusion and complete-copy requirements (F-5, F-6).

D-6. The publication transaction upserts the current network and imported facts, removes obsolete network membership, ways and nodes, reconciles disappearing facts and appends the copy history row. It never uses TRUNCATE, creates persistent staging tables or changes permissions. Agent decision at C:40, without asking: the target schema and service rights permit these DML operations and reserve schema delivery for its owner (F-6 - F-8).

D-7. Preserve fact.id, created_at and its offset, flagged_at, hidden_at and their offsets when an identity is refreshed or returns. Update only imported geometry, step count, source, edit day and the removal marker as the product requires. Never issue a write against vote, account or independent user facts. Agent decision at C:40, without asking: these fields have separate ownership in the target schema and PRD FR-6 - FR-9 requires preserving history and moderation.

D-8. Select vote history in bounded batches and call the same pure vote evaluator the backend uses. Confirmations must outweigh denials over the latest votes of five persons; a confirmation total below 2 can still cause conversion. Detached votes retain their weight and each count as a separate person. D-15 settles the concurrency strategy; the shared evaluator's interface remains unresolved in Q-1 and is not duplicated in the importer. Agent decision at C:40, without asking: this follows M4 and the rule of one source for cross-cutting decisions.

D-9. Source state_at comes from the aware source header instant, with its original offset; osm_edited_on is that element's edit instant converted to a Warsaw day. Server-created timestamps and offsets use the shared clock and configured business zone. Elapsed durations use a monotonic clock. No download timestamp replaces source freshness. Agent decision at C:40, without asking: these are different time meanings fixed by the specification, schema and time standard.

D-10. Keep source directory, malopolskie stem, Kraków relation, timeouts, mapping thresholds and tag lists in third-layer constants next to their rules. Source requests have 30-second redirect/checksum deadlines and a 60-minute whole-run deadline. The whole-run deadline includes acquisition, parsing, derivation, Valhalla preparation, database publication and pointer publication. D-17 replaces the source initiative's separate file-download ceiling. Do not add a schedule. D-16 settles the final-database-publication budget; timeout enforcement and whole-run cancellation remain Q-1. Dependency decisions adopted from source D-11, D-12 and D-15 and mapping D-14, with the explicit download-ceiling change in D-17 and the approved scope extension of D-20.

D-11. Temporary downloads and location storage stay outside the repository and are removed after success, unchanged or failure. Use immutable typed snapshots of pyosmium objects rather than retaining iterator-backed objects across callbacks. Store only the agreed current network and derived facts; do not add a raw OSM archive to the database. Agent decision at C:40, without asking: this implements the existing retention and shared-schema scope.

D-12. Batch database work, parameterize values and explicitly list returned columns. No per-fact vote query, geometry matching of identities, automatic vote, status column or deletion of a fact is added. Integrity and parsing failures abort the whole run rather than silently dropping a required element. Agent decision at C:40, without asking: these are direct consequences of PRD FR-5 - FR-10 and the database, idempotency and quality standards.

D-13. Settle the importer integration contract in this initiative with the user, rather than waiting for an existing contract from Rafał. Decided by the user on 2026-10-04 in response to Q-1. This assigns the contract decisions, not shared backend or schema implementation, to osm_importer. Record the agreed interfaces here for their owners to consume; D-19 permits necessary MVP updates but does not silently resolve other backend questions.

D-14. Support execution on both the hosted demo server and team members' computers. The demo import runs on the server as a separate administrative process using the backend image; local development and write-based tests use the team's local database. Use the same manual entry point, `python -m worker.osm_import`, for the first import and refresh in either environment. The shared backend configuration chooses the database and environment; there is no separate importer connection configuration. The user selected both execution locations on 2026-10-04 in response to the proposed manual command. Keeping critical tests on the local database follows standard_tests.md, not an additional user choice. This decision does not authorize a hosted run or assume that a team computer should connect to the hosted database.

D-15. Briefly freeze changes to the votes of facts being reconciled during final publication. Decided by the user on 2026-10-04, choosing this over reconciliation against a snapshot from the beginning of the transaction. Downloading and parsing hold no fact or vote row locks. Publication uses Read Committed; acquire affected fact rows with FOR UPDATE in ascending id order, then their existing vote rows with FOR UPDATE in fact_id and id order, and read the history for evaluation after those locks have been acquired. Hold these locks through commit or rollback. Vote creation must lock its fact before validating visibility and writing the vote, so a new vote on a frozen fact waits; updates to existing vote identities through account detachment also wait on the locked vote rows. The latest-person selection runs on this protected history. Ordinary reads can continue. The lock order and protected-history read are agent decisions at C:40, without asking: they implement the chosen behavior without a table-wide lock. D-16 bounds publication, including lock waiting; enforcement remains Q-1 and no measured short duration is claimed yet.

D-16. Limit final database publication to 120 seconds. Decided by the user on 2026-10-04, replacing the agent's unapproved 60-second proposal. This is one budget from the start of the publication transaction through commit, including network and fact writes, reconciliation and all lock waiting, not a fresh budget for each statement. Downloading, checksum validation, parsing and derivation happen earlier and are outside this budget. The separate whole-run deadline still applies; publication uses the earlier of its 120-second deadline and the remaining whole-run deadline. Expiration must stop further publication and roll back an uncommitted transaction, preserving the previous copy; release import exclusion only after outstanding work and rollback end. A commit whose outcome is uncertain must not be reported as a proven rollback (R-7). The shared enforcement mechanism remains Q-1. This is an operational ceiling, not evidence that the full dataset can be published within it.

D-17. Remove the separate 15-minute maximum elapsed time for downloading the PBF file. Decided by the user on 2026-10-04 after discussing its overlap with the whole-run budget and the risk of interrupting a progressing transfer on a slow connection. This explicitly supersedes only the PBF download ceiling in source D-12; the archived source initiative is unchanged. Keep explicit connection and read-inactivity timeouts, the 30-second redirect/checksum deadlines and the 60-minute whole-run deadline. A progressing PBF transfer may exceed 15 minutes, but it cannot continue past the whole-run deadline. D-18 sets connection/read timeout values; their enforcement through the shared HTTP client remains Q-1. Downloading still holds no publication transaction or fact/vote row locks, but import exclusion remains held until outstanding work and cleanup end.

D-18. Use a 30-second connection timeout and a 30-second read-inactivity timeout for the source transfer. Decided by the user on 2026-10-04. Read inactivity means waiting without receiving the next data chunk, not 30 seconds for the entire response; a progressing transfer can continue within D-17's whole-run budget. D-10's separate elapsed deadlines for the latest redirect and checksum requests still apply. Apply these values to the importer integration, without changing timeout policies of other backend integrations. Critical deadline behavior remains subject to the selected HTTP client's enforcement contract in Q-1.

D-19. Permit modifications to the MVP initiative and `MVP.md`. Decided by the user on 2026-10-04, lifting the original restriction recorded in the seed. Agent decision at C:40, without asking: these are existing responsibilities beyond the approved importer scope (F-22), so retaining them avoids silently adding app endpoints or another loading workflow here. osm_import consumes this importer's service operation and must not implement a second download, mapping, reconciliation or Valhalla build. D-22. Recover a failed routing-pointer publication automatically on the next manual importer run. Decided by the user on 2026-10-04, accepting the proposed recovery behavior for Q-1. While holding import exclusion, first read the latest confirmed database copy and check its complete prepared routing files. When its pointer is missing or points to an older copy, republish the pointer for that confirmed copy before source acquisition or unchanged-state handling. Recovery alone does not download OpenStreetMap, publish another database copy, rewrite facts or votes, or restart Valhalla. Do not point to files whose completeness or source identity cannot be verified. A separate administrative repair command is not required. D-23 settles the missing-file outcome; D-24 settles bounded uncertain-commit checks; D-25 settles manifest-based completeness validation; the shared enforcement mechanisms remain to be settled in Q-1.

D-23. Stop automatic recovery when the latest confirmed database copy has missing or incomplete prepared routing files. Decided by the user on 2026-10-04, accepting the proposed missing-file outcome for Q-1. Report a named integrity failure, preserve the existing routing pointer and database state, and do not start source acquisition or a new import in that run. Downloading a newer source is not recovery of the confirmed copy. Rebuilding its missing routing data requires a separately specified repair procedure; this decision does not add that procedure to the implementation scope. D-24 settles bounded uncertain-commit checks; D-25 settles manifest-based completeness validation; the shared enforcement mechanisms remain to be settled in Q-1.

D-24. Resolve an uncertain database commit within the same run through at most three reconnection and outcome-check attempts, waiting 1, 2 and 4 seconds respectively before them. Decided by the user on 2026-10-04, requesting three attempts and accepting these intervals. These attempts never repeat COMMIT or database publication. A confirmed committed source copy permits pointer publication only after import exclusion is verified or reacquired. An absent copy proves non-publication only after the original transaction has ended and import exclusion is verified or reacquired; absence alone is not proof of rollback. Reacquisition must retain the zero-wait exclusion policy. All waits and checks remain inside the remaining whole-run deadline; do not start another attempt after it expires. If the outcome cannot be established after the attempts or before the deadline, report an unknown commit outcome and leave the routing pointer unchanged. The next manual run follows D-22 and D-23. The shared connection, exclusion and transaction-lifetime mechanisms that enforce these conditions remain part of Q-1.

D-25. Verify prepared routing files through an immutable per-copy manifest containing the source-state instant, byte sizes and SHA-256 checksums of network.osm.pbf and valhalla_tiles.tar. Decided by the user on 2026-10-04, accepting the proposed completeness verification for Q-1. Write manifest.json only after both files have been successfully prepared and the tile archive's modification time has been set. Before recovery publishes a pointer, verify both files against the manifest and compare its source instant with the confirmed database copy. A missing or invalid manifest, source mismatch, size mismatch or checksum mismatch follows D-23's integrity failure path. Agent decision at C:40, without asking: name the JSON artifact manifest.json inside the existing per-copy directory; this implements the approved verification without changing the shared database schema. D-26 settles reuse and temporary rebuilding of unpublished copies; D-27 settles replacement of incomplete unpublished directories; Q-1 still needs the shared enforcement mechanisms.

D-26. Reuse complete prepared files of an unpublished source copy after acquiring import exclusion, provided D-25's manifest and checksum checks pass and their source instant matches the validated source being imported. Decided by the user on 2026-10-04, accepting the proposed handling of directories left by interrupted imports. Reuse does not bypass source validation, mapping, reconciliation or database publication. Prepare incomplete routing data again in a new temporary directory. Preserve every directory whose source copy was previously committed to the database, including old copies; an existing directory alone does not prove that a copy is unpublished. D-27 settles replacement of an incomplete unpublished target directory.

D-27. Delete an incomplete unpublished per-copy directory instead of retaining it for diagnostics. Decided by the user on 2026-10-04, requesting deletion instead of moving the directory aside and then instructing the agent to proceed. Hold import exclusion and verify against the full osm_copy history that its source instant has never been committed before deleting it. If the database history or exclusion cannot be verified, stop without deletion. Prepare and verify replacement files in a new temporary directory, remove the incomplete unpublished target directory and move the verified replacement into its place before database publication. Preserve all directories belonging to committed copies, even when they are old or incomplete. This authorizes the importer behavior and local verification; it does not authorize a hosted-demo operation. Agent decision at C:40, without asking: finish replacement preparation before removing the old incomplete directory to avoid discarding it when preparation fails.

D-28. Locate an imported node fact at its source coordinates, a non-area way fact at half the way's length, and an area fact at a point strictly inside the area and outside its holes. Decided by the user on 2026-10-04, approving these location rules after verification that the specification, schema and API contract do not already define a representative-point algorithm. Missing geometry references or geometry for which the required point cannot be established fail the entire import and preserve the previous complete copy; no guessed location or silently omitted fact is permitted. These are stored fact locations, not the independently defined routing exclusion points. This decision does not broaden which element types or tags produce facts. D-29 settles the geometry tools and projected interpolation; D-30 settles selected non-area relations; Q-3 still needs dependency readiness checks.

D-29. Use Shapely for geometry operations and pyproj for coordinate transformations. Decided by the user on 2026-10-04, accepting the proposed libraries and metric computation followed by storage in EPSG:4326. Agent decision at C:40, without asking: use PL-1992 (EPSG:2180) as the calculation system for the Kraków import, transform with explicit longitude/latitude order, interpolate a non-area way at half its projected length in original node order, and use representative_point followed by strict interior verification for valid area geometry. Transform results back to EPSG:4326 and verify finite coordinates. Do not repair invalid geometry automatically or substitute a centroid. Nodes retain their original coordinates. Pin compatible library versions and verify transformation availability before closing the technical plan; library selection alone does not claim installed dependencies. - R-9. Only the repository virtual environment of F-16 has the pinned interpreter and tools; checks run through another interpreter do not validate the project.
- R-10. D-20 resolves Valhalla preparation ownership and the PRD is reconciled with specification version 10. Anonymous-hash cleanup is excluded; detached-account votes still require concurrency protection.
- R-11. Database commit and routing-pointer rename are separate operations. The loaded routing service can still serve the old immutable copy after a successful pointer change, and a pointer error can follow a committed database copy. Q-1 must settle how to recover activation of an already committed copy without a second database publication, especially when source comparison otherwise yields unchanged. - R-12. The vote evaluator is not delivered (F-27). Under D-40 the first refresh in which an OpenStreetMap fact disappears fails and keeps the previous copy, until plans/community_facts/ delivers the evaluator and step 4 connects it.
- R-13. The boundary pass keeps every non-area source way in memory, and the network pass keeps every source node, so peak memory grows with the whole Małopolska extract rather than with Kraków. This machine has about 1.7 GB of free memory (F-17). A real import must be measured before the demo depends on it, in the container of D-41 on a machine with enough memory.
- R-14. A non-area relation of the copy whose tags make an amenity present, or an area whose interior point cannot be established, fails the whole import under D-28 and D-30. Real data can contain such an element; the failure then names it and the decision returns to the user rather than being worked around in code.
- R-15. The delivered apply_completion_wait waits without an upper bound for the publication backend to end before PublicationOutcomeUnknown is raised (F-24). In that path the run can exceed its deadline; this is shared-skeleton behavior and is reported to its owner rather than changed here.
- R-16. Windows execution needs ASCII workspace and routing paths (F-30), and real Valhalla tools exist only in the Linux image of D-41; a Windows run can verify everything except the tile build.
