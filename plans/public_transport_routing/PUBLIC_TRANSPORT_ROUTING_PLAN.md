# Plan: Routes with public transport, the optional feature O9

Document state: 2026-10-04, plan closed

## Goal

Build what `PUBLIC_TRANSPORT_ROUTING_PRD.md` asks for, FR-1 - FR-11 with AC-1 - AC-14, in two stages. Stage 1 needs no code of `plans_finished/route_planning/`: the interface in the contract and the other documents, the copy of the GTFS with the routing data of public transport, and the configuration of the switch. Stage 2 joins a route with public transport to `plan_route` on top of the code `plans_finished/route_planning/ROUTE_PLANNING_PLAN.md` builds: the multimodal request, its walking legs through the checks of that plan, the public transport segment, the walking route when public transport is unavailable, the alternative, the operation with the days of the feeds and the archive the routing service serves.

## Decisions

D-1. Two stages. Stage 1, S-1 - S-9, needs no code of `route_planning`; stage 2, S-10 - S-14, edits modules `route_planning` creates and starts only when `service/route_planning.py`, `data/valhalla.py`, `service/route_requests.py`, `service/route_segments.py`, `api/route.py` and `valhalla/start_routing_service.py` exist on the tree, read right before the first edit. The plan of `route_planning` names those modules and functions (F-9). Decided by Rafał on 2026-10-04 in phase B, waiting for that plan rather than naming its functions here.

D-2. Kind of route in the contract. The request of `plan_route` gets the optional field `route_kind`, `walking` or `public_transport`, `walking` when absent. The response gets `public_transport_unavailable`, `true` only when `route_kind` was `public_transport` and the answer is the walking route of PRD FR-4. A segment gets `public_transport`, `null` for a walking segment, and for a public transport segment `{ "vehicle": "tram", "line": "14", "boarding_stop": "Teatr Variété", "alighting_stop": "Cystersów", "departs_at": "2026-10-04T09:12:00.000+02:00", "source": "ztp_krakow_gtfs" }`, an example with stop names the spike reported (F-20), with `vehicle` `tram` or `bus`; such a segment has `state` `no_barrier`, or `not_assessed` when `avoid` is empty, empty `missing_attributes` and `is_marked_wheelchair_no` false, and its `line` runs straight from the boarding stop to the alighting stop (F-21). The client lists each public transport segment as an item of the list of M8 in the order of the route. A request with `route_kind` `public_transport` while the switch is off is refused with 409 `public_transport_disabled`. Agent decision at C:40, without asking, approved with the rest of the contract by Rafał (PRD FR-7); the state with an empty `avoid` decided by Rafał in phase B.

D-3. New operation `read_public_transport`, `GET /api/public-transport`, token optional, no body, answering `{ "is_enabled": true, "feeds": [{ "feed": "GTFS_KRK_T", "published_on": "2026-10-02" }, { "feed": "GTFS_KRK_A", "published_on": "2026-10-02" }, { "feed": "GTFS_KRK_M", "published_on": "2026-10-02" }] }`: whether the client shows the switch, and the three feeds of the GTFS copy the served archive was built from, empty when there is none. It is an operation of its own rather than a field of `read_osm_copy`, so that each operation has one initiative, and `MVP.md` D-12 counts seventeen. Agent decision at C:40, without asking.

D-4. The section Conventions of the contract names the names of stops and lines from the GTFS as a third kind of text in a language in a response, in Polish as the GTFS gives them. Decided by Rafał in the shape, question 4.

D-5. The switch is on where the optional environment entry `PUBLIC_TRANSPORT_ENABLED` is `true`, `false` when absent; the team sets it in an environment only after AC-1 of the PRD passed there, and back to `false` everywhere when the time box ends (PRD FR-8, FR-9). Agent decision at C:40, without asking: whether a route with a tram works is a judgement of a person on a run.

The copy of the GTFS. `ROUTING_DATA_DIR/gtfs/<fetched_at epoch s>/` holds `GTFS_KRK_T.zip`, `GTFS_KRK_A.zip`, `GTFS_KRK_M.zip` and `feeds.json`, `{ "GTFS_KRK_T": "2026-10-02", ... }`; it is filled in a directory `gtfs/.prepare-*` and renamed into place only when all three files came with status 200 and a `Last-Modified`, each is a valid zip holding `agency.txt`, `stops.txt`, `routes.txt`, `trips.txt`, `stop_times.txt` and `calendar_dates.txt`, and `ROUTING_DATA_DIR/gtfs/current` then names it, written through a temporary file and a rename. The day of a feed is the calendar day of its `Last-Modified` in `BUSINESS_TIMEZONE` (F-18). The URLs `https://gtfs.ztp.krakow.pl/GTFS_KRK_T.zip`, `GTFS_KRK_A.zip` and `GTFS_KRK_M.zip` are public addresses of the city's data and are the constant `GTFS_FEED_URLS` of `data/gtfs_source.py` (F-26). Decided by Rafał in phase B for the day of a feed; the rest is an agent decision at C:40, without asking, following F-3.

D-7. Preparing a feed. Each feed is unpacked into its own directory of the ingest input and three columns are rewritten, the other files copied unchanged: in `stops.txt`, `wheelchair_boarding` empty or 0 of a stop whose `parent_station` has 1 or 2 takes that value, as a child stop inherits it in the GTFS reference, and otherwise becomes 1; in `trips.txt`, `wheelchair_accessible` empty or 0 becomes 1; in `routes.txt`, `route_type` 900 becomes 0; the value 2 never changes (F-16). Agent decision at C:40, without asking: the rewrite of the spike, made safe for a child stop of a station marked 2.

D-8. Routing data with public transport. `ROUTING_DATA_DIR/transit/<copy name>-<fetched_at>/valhalla_tiles.tar` is built from `copies/<copy name>/network.osm.pbf` of the copy `current` names, verified by `fetch_osm_routing_manifest`, and the GTFS copy `gtfs/current` names, in a workspace lease of `IMPORT_WORKSPACE_ROOT`: the configuration is `build_osm_valhalla_config` of `VALHALLA_CONFIG_TEMPLATE` with `mjolnir.transit_dir`, `mjolnir.transit_feeds_dir` and `mjolnir.timezone` set to the workspace; then `/bin/sh -c` running `valhalla_build_timezones` into the timezone file, `valhalla_ingest_transit` and `valhalla_convert_transit`, each through `apply_import_process`, and `apply_osm_valhalla_tiles`, which builds the tiles and the archive and stamps it with the instant of the copy (F-4). `ROUTING_DATA_DIR/transit/current` then names the directory, through a temporary file and a rename. Agent decision at C:40, without asking: the build reuses the importer's tools and keeps the files of a copy unchanged (F-3, F-4); the shell carries only the redirection that `apply_import_process` cannot (F-5, F-23).

Agent decision at C:40, without asking.

Agent decision at C:40, without asking.

D-14.
