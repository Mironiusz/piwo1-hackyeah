### Deadline and exclusion contract, Q-1 direction approved

On 2026-10-04 the user answered Yes to PostgreSQL transaction_timeout with a separate exclusion-holder connection and an explicitly uncertain commit outcome. The primitives of D-11 - D-14 were exercised locally in F-21 - F-23. Q-2 - Q-5 now require a durable workspace recovery layer in addition to these database primitives. D-11. Keep import exclusion on a dedicated, unpooled service-account session while publishing on a second dedicated connection created through `data/engine.py`. `data/locks.py` provides `apply_import_exclusion(engine: Engine, workspace_root: Path) -> ContextManager[ImportLease]` and named exceptions `ImportAlreadyRunning` and `ImportLeaseLost`. The user approved the separate-holder direction in Q-1. Use the fixed two-integer keys `IMPORT_ADMISSION_LOCK = (1346983759, 1)` and `IMPORT_PUBLICATION_FENCE = (1346983759, 2)`, with the namespace equal to the integer spelling of PIWO. These are infrastructure constants, not environment entries or product objects. A contender obtains the admission key exclusively with `pg_try_advisory_lock`, then probes the publication fence exclusively with the same try function. Acquire the local workspace lock of D-17 before either database key. Either database refusal releases only its own acquired key and raises `ImportAlreadyRunning` before new source acquisition; durable recovery markers are retained. On success it releases the fence probe and retains the admission lock through caller cleanup. Never put a leased connection back into a pool. Agent decision at C:40, without asking: the second key closes the independently lost-guard write hazard while retaining the user-approved two-connection direction; F-21 and F-22 exercise these primitives without schema or permission changes.

`ImportLease` holds a typed `BackendIdentity(pid: int, backend_started_at: datetime, database_oid: int)` for its guard and each registered publication, and a state of active, lost, cleanup_pending or closed. Before any publication, its dedicated session acquires the shared publication fence, then verifies the expected guard identity and its granted admission lock. Refuse a lost or mismatched guard without sending BEGIN. If the guard disappears after this check, the publication's shared fence still prevents any new contender from passing its exclusive fence probe. Recheck lease validity before subsequent writes and commit, and abort on loss; never recover an old lease by reconnecting. Persist every guard/publication identity in the run journal before source acquisition or BEGIN respectively. Keep the publication fence until that session's database work ends; retain the local workspace lock and guard until outstanding work and caller cleanup end, including the abnormal paths of D-17. D-18. Every external mutating tool must use `data/import_process.py` `apply_import_command(lease: WorkspaceLease, arguments: Sequence[str], deadline: Deadline) -> int`. The accepted tool contract forbids closing that descriptor, unlocking it or detaching an unregistered writer. The consumer must verify its actual tool under this contract before claiming importer readiness. ## Risks

- R-1. Killing only the publication caller or relying on individual statement timeouts can leave work running beyond the shared deadline. Q-1 selected the database-side timeout; actual implementation still needs completion, invalidation and exclusion tests.
- R-2. PostgreSQL transaction_timeout terminates the publication session. The independent guard retains exclusion during orderly cleanup, while the publication's shared fence prevents a new admission after unexpected guard loss. F-21 and F-22 exercise these primitives. After every lock session disappears, no advisory lock can prove that the old Python process has finished local cleanup. Q-2 - Q-5 require one persistent workspace per database and automatic recovery on the next manual launch. D-17 - D-18 add local process protection; actual external tools and Windows behavior remain acceptance runs.
- R-3. Client elapsed time and server transaction time begin at different points. Cap the server limit against the original absolute deadline, check it before commit and conservatively classify lost commit confirmation. Server timeout does not establish the result of an already attempted commit.
- R-4. A disconnected database cannot always prove whether rollback or commit completed. Retaining exclusion without an authoritative completion signal is safer than reporting a proven rollback, but its operational recovery and finite network waits need the concrete protocol required by the answered Q-2 - Q-5.
- R-5. The project image has not been built in this planning phase. Package availability, joint dependency installation, vulnerability audit and SQLAlchemy/psycopg behavior under the actual selected versions remain executable checks; metadata is weaker evidence.
- R-6. The API contract's 404 for an unknown method differs from the framework's default 405. The error adapter must normalize it and omit framework error details.
- R-7. Standard traceback rendering includes raw exception text and SQLAlchemy can include query parameters. Central diagnostic redaction, SQL logging suppression and DEBUG-level failure tests are necessary to satisfy the existing privacy contract.
- R-8. Scratch-object critical tests need maintenance privileges solely for fixture setup/cleanup. Runtime calls must still use the actual restricted service identity, and the critical environment guard must run before those fixtures.
- R-9. Mateusz's importer has an unresolved integration plan and older product-version facts; this initiative must not close its questions or overwrite its files. Skeleton's documented shared interfaces are a delivery input for that work, not proof of its readiness.
- R-10. Kuba's hash-length clarification, initial product revision and product grants are not skeleton tasks. Adding them here would expand the approved PRD and recreate the dependency cycle.
- R-11. The 120-second cap is an operational requirement, not a measured claim that a complete Kraków import fits within it. The actual dataset publication remains Mateusz's measurement.
- R-12. Linux execution cannot establish Docker Desktop/Windows setup correctness. Record the remaining human confirmation plainly when that platform cannot be run.
