## Decisions

D-1. Preserve the agreed root layers and launch contract: `api/`, `service/`, `data/`, `worker/` and `config/`; `api/app.py` exposes `build_app() -> FastAPI`, and `api/__main__.py` exposes `main() -> None`. Start with `python -m api`, one Uvicorn process, `factory=True`, `log_config=None` and `access_log=False`. Skeleton installs no product routers and performs no product read at startup; route-graph initialization belongs to `route_planning`. Adopted from F-1 and F-4. Agent decision at C:40, without asking: a callable application factory and package boundaries deliver the approved foundation without substituting product operations.

D-2. Use the prescribed `data/engine.py` as the only runtime connection factory, exposing `build_engine(statement_timeout_ms: int) -> Engine`. Read only the service address from the configuration facade and enforce `options=-c timezone=UTC`. Keep the previously chosen 5000 ms API statement timeout; administrative engines receive their explicit operation timeout. Use a 5-second connection timeout, `pool_pre_ping=True` and a bounded 5-second pool checkout. Guard/publication connections use dedicated NullPool engines through `build_import_engine(statement_timeout_ms: int) -> Engine`, reusing the same validated service URL and connection options. Bind the runtime facade inside the runtime factory, not at module import, so importing `build_migration_engine` cannot load or require runtime settings. No automatic transaction retry occurs in this foundation. Agent decision at C:40, without asking: these bound infrastructure waits without changing the approved transaction and service-account boundary.

D-3. Runtime dependencies are exact pins of the F-18 versions for FastAPI, Uvicorn, SQLAlchemy, psycopg with its binary extra, Pydantic and Alembic. HTTPX 0.28.1 is a development dependency for programming-interface tests, not an importer HTTP adapter. Record psycopg binary loading as an explicit indirect-runtime dependency where deptry requires it. Verify the complete resolution, Python 3.13 import smoke and pip-audit before accepting these pins; a failure is a finding, not permission to downgrade silently. Agent decision at C:40, without asking: the library families were already agreed, and exact releases complete their executable contract.

D-4. The configuration facade exports validated module constants; it does not expose the migration address, bootstrap password or schema-owner password. `config/settings.py` defines `Settings`, `ConfigurationError` and `ENVIRONMENT_ENTRY_FILES`, and `config/env_file.py` defines `build_environment_values(text: str) -> dict[str, str]`. The facade reads process variables first, `.env.local` second and `.env` last, never `.env.priv`. Parse plain `KEY=VALUE` entries with optional matching quotes, skip blank and comment lines, and reject duplicate keys or malformed lines by key/line only; perform no shell expansion, substitution or implicit interpolation. Agent decision at C:40, without asking: this follows F-6 and gives one explicit file format rather than several loader behaviors.

D-5. ### Deadline and exclusion contract, Q-1 direction approved

On 2026-10-04 the user answered Yes to PostgreSQL transaction_timeout with a separate exclusion-holder connection and an explicitly uncertain commit outcome. The primitives of D-11 - D-14 were exercised locally in F-21 - F-23. Q-2 now concerns the contractual boundary after all lock-holding sessions disappear before local file cleanup ends.

D-11. Keep import exclusion on a dedicated, unpooled service-account session while publishing on a second dedicated connection created through `data/engine.py`. `data/locks.py` provides `apply_import_exclusion(engine: Engine) -> ContextManager[ImportLease]` and named exceptions `ImportAlreadyRunning` and `ImportLeaseLost`. The user approved the separate-holder direction in Q-1. Use the fixed two-integer keys `IMPORT_ADMISSION_LOCK = (1346983759, 1)` and `IMPORT_PUBLICATION_FENCE = (1346983759, 2)`, with the namespace equal to the integer spelling of PIWO. These are infrastructure constants, not environment entries or product objects. A contender obtains the admission key exclusively with `pg_try_advisory_lock`, then probes the publication fence exclusively with the same try function. Either refusal releases only its own acquired key and raises `ImportAlreadyRunning` before acquisition. On success it releases the fence probe and retains the admission lock through caller cleanup. Never put a leased connection back into a pool. Agent decision at C:40, without asking: the second key closes the independently lost-guard write hazard while retaining the user-approved two-connection direction; F-21 and F-22 exercise these primitives without schema or permission changes.

`ImportLease` holds a typed `BackendIdentity(pid: int, backend_started_at: datetime, database_oid: int)` for its guard and each registered publication, and a state of active, lost, cleanup_pending or closed. Before any publication, its dedicated session acquires the shared publication fence, then verifies the expected guard identity and its granted admission lock. Refuse a lost or mismatched guard without sending BEGIN. If the guard disappears after this check, the publication's shared fence still prevents any new contender from passing its exclusive fence probe. Recheck lease validity before subsequent writes and commit, and abort on loss; never recover an old lease by reconnecting. Keep the publication fence until that session's database work ends; keep the guard until outstanding work and caller cleanup end on the orderly path. Values in these metadata queries are bound parameters, and the cleanup monitor selects only pid, backend_start and database identity, never query text or other sessions' data.

D-12. `data/publication.py` owns `apply_publication(lease: ImportLease, run_deadline: Deadline, write: Callable[[Connection], T]) -> PublicationResult[T]`. Start with a dedicated session in autocommit, register its identity and shared fence, and configure `transaction_timeout` through parameterized `set_config` before BEGIN. Fix the effective absolute deadline before sending BEGIN and set one nonzero server budget capped at 120000 ms and the remaining whole-run time. Do not alter transaction_timeout inside the transaction. The shared helper owns BEGIN, COMMIT and ROLLBACK and checks the original monotonic deadline before every statement and commit through connection-scoped SQLAlchemy events. Read Committed and one transaction apply; no two-phase/prepared transaction, nested transaction, callback-managed completion, detached write task or reconnect is permitted. The callback performs the importer's parameterized writes synchronously on the supplied connection. Dispose of the dedicated engine after database completion rather than reuse its session. Do not combine the normal API 5000 ms statement limit with a publication that is explicitly allowed a longer lock wait. The transaction ceiling is enforced by the server even while the client is idle; exact production-duration, driver-event and commit tests remain implementation criteria. Adopted from Q-1 and F-10; Agent decision at C:40, without asking: this makes the approved budget nonrenewable and avoids implicit setup transactions.

D-13. Distinguish `PublicationResult[T]` with outcome `committed` from `PublicationRolledBack` with a safe reason code and `PublicationOutcomeUnknown`. A confirmed COMMIT response establishes success. An acknowledged rollback or a verified terminated backend before COMMIT was attempted establishes rollback; a timeout alone does not. Track whether COMMIT was attempted before the actual send, conservatively. Connection loss or interruption during that phase without authoritative confirmation yields the unknown outcome even when later rollback on the broken client returns without error. No automatic retry or routing-pointer update follows an unknown outcome. Importer-owned recovery can inspect its source-state identity under exclusion later; skeleton implements no copy lookup or recovery command. The user approved this distinction in Q-1; F-21 verifies only the before-commit rollback primitive, not uncertain-commit recovery.

D-14. After a publication timeout, prevent further statements, invalidate its connection and verify that the registered backend identity has disappeared before closing the guard. Successful explicit rollback instead requires its acknowledgement and an idle driver transaction status; no exception text is a completion signal. The cleanup monitor uses the guard's autocommit session, not a cached statistics transaction. Each check has a 5000 ms statement limit, checks only the run-owned identity and never issues privileged termination. A client close, completed future, cancelled timer or attempted rollback is not evidence by itself. On an inconclusive check set cleanup_pending, log the named `PublicationCleanupUnconfirmed` condition without protected values, and retain the guard while repeating checks at one-second intervals; do not exit its context or claim final rollback until completion is confirmed. A lost guard is never re-created as the same lease. The publication-held fence protects outstanding database work on that failure path (F-22), but waiting for local file cleanup after every lock session is lost remains the explicit decision in Q-2. Agent decision at C:40, without asking: typed identity plus fresh same-role queries provides the approved completion evidence without maintenance privileges.

D-15. Tests use invented local data independent of the product revision. Local critical publication tests create a uniquely named scratch table with the migration identity in a fixture, grant the service role only the scratch rights and remove precisely that fixture object afterwards. This is test isolation, not a product schema change. Register each created object before executing the test; never delete by a broad prefix. Use the actual restricted service role for every exercised runtime connection. Locale, role-attribute and DDL-denial checks require no product object. PostGIS extension creation, product grants and alterations of product objects stay with Kuba. Agent decision at C:40, without asking: F-15 and F-16 require independent real-database evidence.

D-16. Update `docs/standards/README.md`, `decision_registry.md` and `naming_registry.md` with the first implemented backend, not with this draft. Record actual consumer interfaces in `docs/setup/backend.md` and link the runbook from the root README. Layers with no domain rule receive no empty code-unit document pair; record the creation condition in `agent_docs/memory/<layer>/_shared.md` at implementation completion. The administrative/publication mechanisms need a concise description where their construction and lifecycle are documented, without claiming product rules were delivered. Agent decision at C:40, without asking: F-20 and `standard_documentation.md` distinguish planning from implemented state.

## Risks

- R-1. Killing only the publication caller or relying on individual statement timeouts can leave work running beyond the shared deadline. Q-1 selected the database-side timeout; actual implementation still needs completion, invalidation and exclusion tests.
- R-2. PostgreSQL transaction_timeout terminates the publication session. The independent guard retains exclusion during orderly cleanup, while the publication's shared fence prevents a new admission after unexpected guard loss. F-21 and F-22 exercise these primitives. After every lock session disappears, no advisory lock can prove that the old Python process has finished local cleanup; Q-2 is a contract decision, not an engineering detail to guess.
- R-3. Client elapsed time and server transaction time begin at different points. Cap the server limit against the original absolute deadline, check it before commit and conservatively classify lost commit confirmation. Server timeout does not establish the result of an already attempted commit.
- R-4. A disconnected database cannot always prove whether rollback or commit completed. Retaining exclusion without an authoritative completion signal is safer than reporting a proven rollback, but its operational recovery and finite network waits need a concrete contract in Q-2.
- R-5. The project image has not been built in this planning phase. Package availability, joint dependency installation, vulnerability audit and SQLAlchemy/psycopg behavior under the actual selected versions remain executable checks; metadata is weaker evidence.
- R-6. The API contract's 404 for an unknown method differs from the framework's default 405. The error adapter must normalize it and omit framework error details.
- R-7. Standard traceback rendering includes raw exception text and SQLAlchemy can include query parameters. Central diagnostic redaction, SQL logging suppression and DEBUG-level failure tests are necessary to satisfy the existing privacy contract.
- R-8. Scratch-object critical tests need maintenance privileges solely for fixture setup/cleanup. Runtime calls must still use the actual restricted service identity, and the critical environment guard must run before those fixtures.
- R-9. Mateusz's importer has an unresolved integration plan and older product-version facts; this initiative must not close its questions or overwrite its files. Skeleton's documented shared interfaces are a delivery input for that work, not proof of its readiness.
- R-10. Kuba's hash-length clarification, initial product revision and product grants are not skeleton tasks. Adding them here would expand the approved PRD and recreate the dependency cycle.
- R-11. The 120-second cap is an operational requirement, not a measured claim that a complete Kraków import fits within it. The actual dataset publication remains Mateusz's measurement.
- R-12. Linux execution cannot establish Docker Desktop/Windows setup correctness. Record the remaining human confirmation plainly when that platform cannot be run.
